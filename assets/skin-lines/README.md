# Reusable skin-line production pipeline

This infrastructure contains **no released skin lines**. The owner creates and approves each collection. Never ship an invented skin, texture, or case automatically.

## Existing weapons

The live catalog currently contains 24 approved weapon masters and can grow without a fixed upper bound. Each has a source-neutral WebP, converted standard 1600x800, 800x400, and 400x200 output, and a paint-main mask in `assets/skin-lines/masks/`. The renderer uses that exact silhouette and transparency and preserves original hardware detail wherever masks exclude it. Masks were initially autogenerated; review and hand-refine each mask before final art approval. Existing masks are preserved by subsequent builds.

## Blackout Case (released, limited to five weapons)

The owner released Blackout as a **25-coin purchasable themed case** with
`released:true` and the initial `weapons` filter:
`["FN FAL","RPG-7","Desert Eagle","SPAS-12","AWP"]`.
Its three repeatable WebP materials are still metal camouflage, dark wood grain,
and matte black other. The generator produces 15 outputs for these five weapons
(400/800/1600 pixel widths), preserving the neutral master silhouettes.

In **Cases**, buy a sealed **Blackout Case** for 25 coins, open it from inventory,
and collect the actual Blackout skin reward. Saved condition grades, market pricing,
trading and reload persistence work like other cosmetics. The normal Arsenal Case
remains entirely separate.

**Tier odds:** Blackout currently has no Common or Legendary weapons. Published
rarity weights are normalized across the tiers actually represented in this case:
Uncommon 20/29.5 ≈ 67.80%, Rare 7.5/29.5 ≈ 25.42%,
Super Rare 2/29.5 ≈ 6.78%. Each available weapon of a tier is equally likely
within that tier. The Arsenal Case retains its original 70/20/7.5/2/0.5 probabilities.

To expand Blackout, add more supported weapon names to its `weapons` filter,
or remove the filter entirely once the owner approves a full-catalog release.
No additional manually generated weapon art is needed; rerun the procedural
build/verification pipeline to create the new images.

## Adding an owner-created line

1. Place the owner's three seamless PNG/WebP textures in `assets/skin-lines/textures/` (one each for metal, wood, other). For legacy single-material lines a single `pattern.texture` still works.
2. Add **one** entry to `assets/skin-lines/lines.json` following the schema below. Start with `released:false` until owner approval and the assets have been reviewed.
3. Change to `released:true` only after approval. Run `python scripts/build_skin_lines.py` then `python scripts/build_skin_lines.py --check`.
4. GitHub Actions regenerates 400px/800px/1600px WebPs and synchronizes the browser registry. A line automatically registers one variant per active catalog weapon and its own case. It never alters the original Arsenal Case pool.

### Definition template (documentation only; not a game skin)

```json
{
  "id": "owner-chosen-slug",
  "name": "Owner-Chosen Name",
  "description": "Written by the owner",
  "released": false,
  "multiplier": 2,
  "casePrice": 25,
  "palette": ["#1b1b1b", "#dddddd"],
  "pattern": {
    "texture": "assets/skin-lines/textures/owner-chosen-slug.png",
    "tileWidth": 300,
    "offsetX": 0,
    "offsetY": 0,
    "opacity": 0.85
  }
}
```

Remove `pattern` to apply just a palette. The pattern scales/repeats without changing the neutral master, and is clipped to the weapon paint mask. These placeholders are not entries in the live registry.

### Three-material recipe: use the actual weapon maps

Add an entry to `assets/skin-lines/lines.json` using **materials** (not `pattern`).
These entries are only examples; the shipped `lines.json` stays empty until the owner requests publishing a line.

```json
{
  "id": "owner-selected-line",
  "name": "Owner Selected Line",
  "description": "Three separately masked materials",
  "released": false,
  "multiplier": 2,
  "casePrice": 25,
  "materials": {
    "metal": {
      "texture": "assets/skin-lines/textures/example-metal.png",
      "tileWidth": 480,
      "offsetX": 0,
      "offsetY": 0,
      "opacity": 0.96
    },
    "wood": {
      "texture": "assets/skin-lines/textures/example-wood.png",
      "tileWidth": 620,
      "offsetX": 0,
      "offsetY": 0,
      "opacity": 1
    },
    "other": {
      "texture": "assets/skin-lines/textures/example-other.png",
      "tileWidth": 350,
      "offsetX": 0,
      "offsetY": 0,
      "opacity": 1
    }
  }
}
```

**How masks work:** for each weapon in the approved catalog, the generator reads
`assets/skin-lines/materials/<slug>--material-1600.png` and its corresponding neutral image.
Every visible pixel must belong to exactly one material: pure red = **metal**, pure green = **wood**,
pure blue = **other**. The `materials.metal` image is clipped to red pixels, wood to green,
and other to blue; no texture crosses material boundaries. The alpha must match the original
weapon exactly. Profiled `protectedRects` remain unpainted, and basic weapon shading is
preserved rather than stamping flat squares over the neutral source.

**Input format:** `materials` must contain all three keys. Each takes the same tiling parameters
as the legacy `pattern` definition, but each key can use independent `tileWidth`,
`offsetX`, `offsetY`, and `opacity`. Source textures must be PNG or WebP,
inside `assets/skin-lines/textures/`. Do not use a single `pattern` together with
`materials`. Unlike the older `pattern` recipe, the three-material recipe does **not**
require a palette; it uses the uploaded artist's actual texture colors. The original
two-color palette and single-pattern format remain backward compatible.

**Review warning:** metal/wood/other classifications are reviewed drafts, not guaranteed
perfect semantic segmentation. Any regions labeled **other** will receive the other texture
even if physically wood or metal. Inspect and refine mask boundaries before releasing a line.
Rendering changes neither the original approved masters nor the 10 separately uploaded custom skins.

### Test and safety rules

- Do not overwrite original finished custom skin art.
- Export weapon-only WebPs with genuine transparency, no outside glow or backgrounds.
- All line output alpha masks must match the normalized neutral master pixel for pixel.
- Keep player IDs, existing owner-approved cosmetics, saved market prices, and wear grades intact.
- For now new cases inherit each weapon's existing rarity tier and the game's published tier odds.
- The browser reads only entries explicitly marked `released:true`.
- Execute `node tests/core.cjs` and `node tests/smoke.cjs` before merge.

## New weapon onboarding (dynamic catalog)

Adding a weapon no longer requires manually editing `index.html`, `upgrade.js`, or `market/skin-lines.js`. Every approved item is registered once in `assets/manifest.json`; `scripts/sync_weapon_catalog.py` generates `assets/weapon-catalog.js` with the live drop catalog, source image paths and slugs. Browser wear, procedural skins and themed cases use those generated mappings.

**Draft the new master without releasing it:**

```bash
python scripts/onboard_weapon.py --image /path/to/weapon.png --name "Long Double Barrel Shotgun" --slug double-barrel-shotgun --tier 1 --value 28
```

This preserves the exact silhouette, centers without cropping, and writes 400/800/1600px transparent WebP files under `assets/weapon-staging/<slug>/`, along with a draft material mask, silhouette map, paint-main mask, visual overlay and editable `profile-template.json`. Pixels whose material is unknown default to OTHER (blue): rust is **not** applied to guessed metal. The tool does **not** register an item or alter any saved game when staging.

**Review the mapping before releasing:** edit the staged `profile-template.json` and supply the metal/wood/polymer rectangles as normalized `[left,top,right,bottom]` coordinates in its `wear` object. For example, `"metalRects": [[0.30,0.25,0.80,0.45]]`. Add a separate JSON file with at least two independently verified points, e.g. `[["metal",0.55,0.35],["other",0.55,0.72]]`; at least one point must identify metal or wood. Review `material-review.png` and make sure every part receives the intended surface class. Rectangles are **drafts**, not a semantic segmentation guarantee.

**Publish only after explicit owner approval:**

```bash
python scripts/onboard_weapon.py --image /path/to/weapon.png --name "Long Double Barrel Shotgun" --slug double-barrel-shotgun --tier 1 --value 28 --profile assets/weapon-staging/double-barrel-shotgun/profile-template.json --landmarks /path/to/double-barrel-landmarks.json --publish
python scripts/audit_material_maps.py --output tests/material-review-sheet.png
python scripts/sync_weapon_catalog.py --check
node tests/core.cjs
```

Publishing verifies human-selected points against actual masked pixels, blocks duplicate names and masters, adds the approved catalog item + profile + landmarks, generates the actual 3 material maps and native-resolution WebPs, refreshes the browser registries, and builds any already **released** universal skin line for the new model. No separately owner-approved custom skin changes. Existing save identities and wear grades remain unchanged; rarity is explicitly chosen and existing tier odds remain intact. Commit all generated PNG/WebP and registry files together after tests pass.

The CI build checks manifest/catalog sync, synthetic staging, exact source-alpha parity, masks, material landmarks, skin outputs and core gameplay. The number of weapons is derived from the manifest, not an assumed count of 24.

## Full silhouette/material maps (wear 0.5.5a)

Every master must generate both `assets/skin-lines/materials/<slug>--silhouette-1600.png` and `<slug>--material-1600.png`. Metal, wood and other are exhaustive and mutually exclusive inside the exact source alpha. Unknown areas are classified **other**, never metal.

Generate with `python scripts/build_material_maps.py`, then run `python scripts/build_material_maps.py --check`. Keep existing `paint-main` masks separate; those are for coating, not material identity.

Review and correct draft material regions in `paint-profiles.json` before the first skin line is approved. Material-aware rust and other wear effects use these generated map files at runtime.
